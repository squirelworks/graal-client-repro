# graal-client-repro v4.0.1

Development checkpoint; this is not a polished or fidelity-certified release. The version is v4.0.1 as requested by the owner; the previous published suite release is v0.0.4.

## Changes since v0.0.4

- Shared C++ host/frame integration and explicit script selection, including independent selection fixtures.
- A bounded Torque DSO v33 reader with allocation limits, decoded instruction boundaries and validated control-flow targets.
- Execution of a bounded integer/branch VM subset from serialized DSO input.
- Native console-function dispatch with validated argument counts and corrected signed integer formatting for the documented Linux 3.04 scope.
- Legacy GS1 variable ownership fixes and documented movement corrections.
- Scoped CI selection with shared-code and workflow integration coverage.

These describe merged work, including PRs #167–171 and #181–185. They do not certify complete Torque compatibility or all historical client behavior.

## Packaging and validation

The combined release workflow builds/tests and packages the legacy Pascal clients on Linux and Windows, and calls the Java, Zelda Online and Game Boy workflows for their own artifacts. C++ host/DSO/native/VM changes are source-tree checkpoint changes; this workflow does not produce separate packaged C++ executables for them. Per-client historical notes remain in each client folder.

macOS builds and testing are deferred until polishing. No macOS support or validation is certified by this release. Linux/Windows release build results must be checked in the linked workflow run before publication; this drafted text is not evidence of a successful run. The optional long stress soak is off by default and must not be described as passed when skipped.

## Known limits

- Bounded DSO/native/VM coverage is not a complete engine, renderer, scheduler, object model or gameplay implementation.
- Unity support is not included or required for this checkpoint. Worlds work remains incomplete.
- Runtime fidelity varies by historical client; read each folder's README and RELEASE_NOTES for its unresolved behavior.
- No original client installation or proprietary game assets are supplied by this release preparation. Use assets you are authorized to provide.

## Publishing

Run release-all at the reviewed commit with version `v4.0.1`, publish `no`, macos `no`, dry_run `no`, and only left empty for the full suite. Inspect the successful Linux/Windows builds and component jobs, the attached files and these notes in the generated draft, then publish manually. Do not use release-combine for this new build.

Draft creation does not publish the release. The workflow adds the exact artifact list to these notes.
